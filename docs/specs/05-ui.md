# Stage 5: warm, clear UI + sync visibility + UI tests

## Goal

A simple, uncluttered UI in warm colours, a smooth "open a todo" animation, and visible sync
state, so the user always knows whether their changes reached the server. Plus the first
Compose UI tests. Timebox: about 2.5 h. Behaviour of sync/data does not change.

## 1. Theme (`ui/theme`)

- `AppTheme` wrapping `MaterialTheme`, used by `App()`. Light and dark colour schemes, both
  fully defined (no default purple anywhere), following the system setting.
- Warm palette (starting point, adjust if contrast needs it):

  | token | light | dark |
  |---|---|---|
  | primary (terracotta) | `#B5532E` | `#F0A07E` |
  | onPrimary | `#FFFFFF` | `#4A1A08` |
  | secondary (honey) | `#C98A1E` | `#E8B65A` |
  | background (cream) | `#FFF8F1` | `#1C1612` |
  | surface | `#FFFCF8` | `#26201B` |
  | surfaceVariant (sand) | `#F2E5D7` | `#3A3029` |
  | onSurface (warm brown) | `#2D211A` | `#F2E6DC` |
  | onSurfaceVariant | `#6B5A4E` | `#CDBCAF` |
  | outline | `#D8C6B6` | `#5A4C42` |
  | error | `#B3261E` | `#F2B8B5` |

- Text/background pairs must meet WCAG AA (4.5:1 for body text). Check the main pairs and
  state the ratios in the report.
- Shapes: rounded corners (cards ~16 dp, FAB/chips fully rounded). Default Material type
  scale, no custom fonts. Spacing on a 4/8 dp grid; generous padding.
- Colours live only in the theme; screens use `MaterialTheme.colorScheme` tokens, never hex.

## 2. List screen

- Each todo is a card (surface colour, subtle tonal elevation): checkbox, title, one line of
  description (ellipsized), a small "not synced yet" icon when the todo is pending.
- Done todos: title with strikethrough + muted colour, animated (not an instant jump).
- Checkbox toggle animates (brief scale bounce + colour).
- `animateItem()` for insert / delete / reorder.
- Empty state: friendly icon + one line of text + hint to tap the button.
- Extended FAB "New todo" (collapses to an icon when scrolling down; optional).

## 3. Opening a todo (the main animation)

- **Shared element transition** from the list card to the detail screen: the card's bounds
  morph into the detail screen container (`SharedTransitionLayout` + `sharedBounds` with the
  navigation `AnimatedContentScope`), and the title text is a shared element. Back (button,
  gesture, Android predictive back) runs it in reverse.
- New todo (FAB) uses the FAB → screen container transform the same way if simple; otherwise a
  fade + slight scale.
- Duration ~350 ms, Material "emphasized" easing. No animation on the very first composition.
- If shared elements misbehave on a target, fall back to fade-through for that target and say
  so; do not ship a janky transition.

## 4. Sync visibility

- Domain: `Todo` gets `isSynced: Boolean` (from `syncStatus`). A small domain interface
  `SyncStatusRepository` exposes `Flow<SyncOverview>` (`Synced`, `Syncing`,
  `Offline(pendingCount)`), implemented in `data` from `SyncEngine.state`, the pending count and
  the live connection (connected = received `hello`). The UI depends only on the domain
  interface (keeps the Konsist rule "ui must not import data").
- List top bar shows a small status chip:
  - `Synced` (cloud-done icon, calm colour),
  - `Syncing…` shown only if syncing lasts > 300 ms (avoid flicker on fast syncs),
  - `Offline · N waiting` (cloud-off icon, secondary colour) when the server is unreachable.
  Transitions between states crossfade.
- Pending todos show the small icon from section 2; it disappears when synced (animated).

## 5. Detail screen

- Same warm styling; title as a large borderless field, description below, multi-line.
- Small footer: "Edited <relative time>" from `updatedAt` (needs `updatedAt` in the domain
  model too; format "just now", "5 min ago", "yesterday", else a date).
- Keep all existing behaviour (save on back, delete, process-death rules).

## 6. Accessibility

- Content descriptions on icons (checkbox state, sync icon, status chip), touch targets
  ≥ 48 dp, state not conveyed by colour alone (icons + text), all strings in `strings.xml`.

## Tests (must pass)

Compose UI tests (`runComposeUiTest`) on the JVM (`jvmTest`), with fake repositories and the
real ViewModels; prefer semantics/text over test tags:
- list shows todos; done todo is marked as done in semantics; empty state shown when empty.
- tapping the checkbox toggles the todo (fake repository receives it).
- pending todo shows the "not synced" icon; synced one doesn't.
- status chip: `Synced`, `Offline · 2 waiting`; `Syncing…` not shown for a 100 ms sync,
  shown for a 1 s sync (virtual clock).
- full flow: FAB → detail → type title → back → the new todo is in the list.
- theme: light and dark schemes define every colour used (no default Material purple) — a
  simple unit test comparing against `lightColorScheme()` defaults is enough.
- relative-time formatter: unit tests for the buckets.

Run all suites; update the coverage floor only if I ask (report the new number).

## Manual check

Android + desktop, light and dark mode: colours, contrast, open/close animation (incl.
predictive back on Android), checkbox and list animations, status chip with
`docker compose pause` (offline · N waiting) and `unpause` (back to synced).

## Out of scope

Custom fonts, swipe-to-delete, tablet / two-pane layouts, iOS-specific polish, screenshot tests.
